After upload:

oxide.reload WebsiteVipBridge
websitevip.rp.status

Why:
- WebsiteVipBridge v1.4.9 polls signed RP purchase requests from
  /api/server/rp-purchases.php and posts signed results to
  /api/server/rp-purchase-result.php using the existing Raidlands HMAC bridge
  headers.
- The bridge checks the live ServerRewards balance through the ServerRewards
  plugin API, debits RP only after balance confirmation, and saves processed
  request IDs in oxide/data/WebsiteVipBridge/rp_purchases.json.
- Duplicate polls or plugin reloads return the saved confirmed, rejected, or
  failed result for the same request ID instead of taking RP a second time.
- Insufficient fixed purchases are rejected. Insufficient renewal requests are
  rejected with subscription_status=past_due so the website can let the current
  entitlement expire normally.

Notes:
- Keep oxide/data/WebsiteVipBridge/rp_purchases.json when migrating or
  restoring the live server; deleting it removes the local idempotency ledger.
- RpPurchaseProcessedRetentionDays defaults to 0 so processed request IDs are
  kept indefinitely unless you intentionally choose a pruning window.
- Confirm ServerRewards is loaded before testing RP purchases.
