Raidlands RoamBots bot-vs-bot damage diagnostics - 2026-07-06

What changed:
- RaidlandsRoamBots is now v0.3.59.
- Different-clan bot hits still keep normal Rust damage when it is working.
- The bad sustained-fire fallback idea has been removed; RoamBots no longer injects bot-vs-bot HP loss without a real Rust damage hook.
- The debug side panel now includes `Dmg:` telemetry showing bot weapon-fire hooks and the latest damage-hook classification.
- `Dmg:` can distinguish enemy_bot, enemy_bot_floor, same_clan_block, untracked_attacker, untracked_victim, player_to_bot, and bot_to_player.
- `raidbots.list` legacy combat diagnostics now inspect the bot's actual memory target, including enemy bots, instead of the nearest real player.
- Advisor HTTP submissions now require a current real-player fight, not just a recent real-player engagement signal.
- After the existing engagement check, RoamBots now verifies the active memory target or candidate target ids resolve to an engageable real player before any OpenAI-compatible request can be submitted.
- Bot-vs-bot clan-war decisions now stay on deterministic fallback and report advisor_skipped_not_fighting_real_player instead of spending API calls.
- Bot-vs-bot same-clan friendly hits now clear the invalid target and stop the attacker instead of letting it keep firing into cancelled damage.
- Different-clan bot hits now keep normal Rust damage when it is working, but legacy scientist hits that arrive with effectively zero damage are raised to a small weapon-class damage floor so clan-war fights can actually end.
- This directly investigates the live symptom where two roam bots stand about 5m apart, shoot each other, and neither loses HP.
- Live config had Map markers enabled with Radius=8 and Alpha=0.65, so the missing-marker issue was not a bad toggle.
- Native debug map markers now use a calibrated visible display-size conversion instead of the too-small literal meter conversion.
- With "Debug Bot Map Marker Radius" set to 8, RoamBots now publishes a native map radius of about 0.047.
- RoamBot marker entities now set globalBroadcast=true before spawn so clients can receive them as map-level debug entities.
- The /raidbots admin Debug tab now labels that control as "Marker size".
- The checked-in marker alpha default is reduced from 0.85 to 0.65 so clustered bot markers stay easier to read.
- This fixes both extremes seen in live testing: first map-sized red/yellow/green disks, then invisible markers.
- RoamBots exposes a managed NPC lending API for RaidlandsEvents:
  - REBOT_SpawnGroup(requestJsonOrDictionary)
  - REBOT_SpawnSingle(requestJsonOrDictionary)
  - REBOT_DespawnGroup(groupId, reason)
  - REBOT_DespawnForEvent(eventInstanceId, reason)
  - REBOT_GetBotOwner(entityIdOrEntity)
  - REBOT_SetGroupObjective(groupId, objectiveJsonOrDictionary)
  - REBOT_SetGroupLeash(groupId, center, radius)
  - REBOT_IsBot(entityIdOrEntity)
- Managed/event-owned bots carry owner, event instance, group, profile, difficulty, leash, and objective metadata.
- Ambient population maintenance now counts only ambient bots, so event-owned bots are not trimmed by Target Population and do not trigger ambient refills when they die or despawn.
- Managed spawn requests accept JSON strings or Oxide-friendly dictionaries with EventInstanceId, GroupKey, Profile, Difficulty, Count, HealthMultiplier, TeamKey, SpawnMode, SpawnPoints, Leash, Roam, LootMode, and ReturnEntityIds.
- Unmapped profile, weapon, armor, behavior, and loot details are accepted as metadata and returned as warnings while RoamBots falls back to configured kits/tactics.
- Existing BGrade-facing APIs remain available:
  - API_IsRaidlandsRoamBot(BaseEntity)
  - API_GetRaidlandsRoamBotCombatKey(BaseEntity)
